**Questions for the owner**

**Q1. When the saved file is damaged, what happens to it?**
On start the program reads the shelf file. If it's damaged, it either keeps the file where it is or moves it out of the way. Here the design moves it aside and starts an empty file; the spec leaves it in place, so the next save overwrites it.
- (a) Move it aside as `&lt;file&gt;.bad` (numbered if one exists) and start empty; the person can recover the old content by hand.
- (b) Leave it in place and start empty; the next save replaces it and the old content is lost.
- (c) Refuse to start, with an error naming the file, until the person fixes or removes it.

**Q2. When the file exists but can't be read (no permission, disk error), what does the calling program get?**
`loadShelf` returns a list of items and the library has no screen, so a message has to come through the return value or an error. Returning an empty shelf risks the next save replacing the unread file.
- (a) An error naming the file and the reason; nothing is loaded and nothing is overwritten.
- (b) An empty shelf plus a warning the program can show, with the words set in the design.

**Q3. Is there older saved data to support?**
The spec reads items without a quantity, "saved by an older version", as quantity 1. Shelf has never saved anything, so no such files exist yet.
- (a) Drop the scenario and put a version number in the file from day one.
- (b) Keep it as a rule for hand-edited files: an item without a quantity counts as 1.
- (c) Treat such items as damaged data, so Q1 applies.
